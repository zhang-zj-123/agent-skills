# Anki 卡片

把一个主题的内容拆成可长期复习的问答卡，产出 `.apkg` 牌组包。

## 环境

需要 `genanki`。使用这个解释器（已装 genanki 与 zstandard）：

```
C:\Users\ZQ\.workbuddy\binaries\python\envs\default\Scripts\python.exe
```

系统默认的 `python` 没有装，直接调用会报 ModuleNotFoundError。

## 工作流

### 1. 确认来源与规模

一次问清，最多三个问题：

- 内容来源：文档 / 视频字幕 / 网页 / 用户口述
- 规模：不确定时给三档——速览约 15 张 / 标准约 40 张 / 完整 60 张以上
- 是否要"大局型面试题""技术选型""整体架构"这三类（最容易漏，也最有用）

### 2. 拆卡并写 Markdown 稿

动手前读 `references/card-writing.md`，按其中的拆卡标准与答案结构写。核心三条：一张卡一个知识点；答案 1～3 行；加粗只给关键词。

产出文件严格使用下述格式——脚本靠它解析，格式错了就抽不出卡：

```markdown
# <主题> 记忆卡片

> 来源：<文档 / 视频 / 网页>
> 卡片数：N 张 · 类型：问答卡（正面 / 背面 / 标签）

---

## 一、概念与背景（6 张）

### 01
- **正面**：问题？
- **背面**：答案，关键词用 **两个星号** 包住。
- **标签**：主题::分组
```

硬性约束：

| 项 | 要求 |
|---|---|
| 卡片标题 | `### ` + 两位数字，从 01 起连续、不重复 |
| 字段 | 每张卡三行：`- **正面**：`、`- **背面**：`、`- **标签**：`，可再加 `- **补充**：`（显示为灰色小字） |
| 每条内容 | 必须写在一行内，不要换行 |
| 标签 | 必须包含 `::`，格式 `主题::分组`，建议全小写 |
| 冒号 | 中英文冒号都接受 |

### 3. 让用户核对（不可跳过）

用 `present_files` 打开 md 稿，并说明：

- 张数与分组分布（用表格）
- **哪些卡可能不准**——转写错误、推断内容、来自厂商材料的数字
- 是否要压缩张数或补某一类

用户确认后才生成 apkg。这是固定协作节奏：先看内容，再落文件。

### 4. 生成 apkg

```bash
python scripts/build_apkg.py --md 卡片.md --deck "All::1 - Network::1 - SRv6"
```

需要分批时用 `--groups`，按编号区间切：

```bash
python scripts/build_apkg.py --md 卡片.md --deck "All::1 - Network::1 - SRv6" \
    --groups "1-46:基础,47-96:冲刺" --out "D:\ZS\学习笔记\卡片牌组"
```

| 参数 | 作用 |
|---|---|
| `--md` | 卡片稿路径（必需） |
| `--deck` | 牌组全名，`::` 形成层级 |
| `--groups` | `"1-46:基础,47-96:冲刺"`，生成 `<前缀>__1 - 基础.apkg` 等 |
| `--out` | 输出目录，默认为 md 所在目录 |
| `--lowercase-tags` | 标签整体转小写 |
| `--dry-run` | 只校验不生成 |
| `--name` | 覆盖文件名前缀（默认取牌组末段的主题名） |
| `--tsv` | **默认不要加**。仅在用户明确要求表格/纯文本时使用；用户要的是能双击导入的 apkg |

交付只给 apkg，不要顺手加 TSV——多一个文件反而增加选择成本。

脚本会先校验编号连续性、字段完整性、标签格式、`**` 是否闭合，不通过则中止。

### 5. 交付

`present_files` 给出 apkg，说明牌组路径、每包张数、导入方式（双击 apkg）。补一句：guid 由"牌组名 + 卡号"固定生成，内容改了重跑会**更新**原卡而不是新增副本。

## 样式

`assets/card.css` 是 GitHub 风明暗双主题（中文微软雅黑 17px、问题 19px 加粗、`<b>` 蓝色 #0b6bcb、代码灰底圆角、支持 nightMode）。要换视觉风格直接改这个文件，不必动脚本。

## 常见坑

1. **临时脚本不要命名 `inspect.py`**。它在 sys.path 首位会遮蔽标准库，genanki 的导入链（cached_property → asyncio → inspect）直接崩，报错还指向无关文件。
2. **TSV 必须是 UTF-8 无 BOM**，否则首个字段会带 `\ufeff`；也不要让用户用 Excel 打开另存，编码和 Tab 都会被破坏。
3. genanki 输出的 apkg 只含 `collection.anki2`（旧版容器），新版 Anki 能正常导入，**不必**自己补 `collection.anki21b`。
4. 所有主题共用同一个 `MODEL_ID`，模板才会复用；换主题不要改它，否则 Anki 里会堆出多个同名模板。
5. 读别人给的 apkg：新版是 `collection.anki21b`（zstd 压缩的 SQLite，需 `zstandard`），`collection.anki2` 可能只是"请更新到最新版"的占位壳；旧版的 `col` 表里才存 models/decks JSON。
6. 分批要按**编号区间**切，不要按标签字典序切。标签顺序与章节顺序常不一致（例如"可靠性 / 演进 / 场景"排在"跨域"之后，但它们属于基础部分），按字母序切会漏卡。脚本末尾会打印"未落入任何分组"。
