# anki-cards

把文档、字幕、笔记或网页整理成可以直接双击导入的 Anki 牌组。

先产出一份 Markdown 卡片稿供你核对内容，确认后再打包成 `.apkg`。适合把一份材料变成能长期复习的问答卡，而不是一次性的读书笔记。

---

## 它解决什么问题

- **拆卡有标准**：一张卡只测一个知识点，答案控制在 1–3 行，避免"背下一整段话"的无效卡片
- **内容先核对**：卡片稿是纯 Markdown，改字、删卡、调顺序都在导入前完成，不用在 Anki 里返工
- **样式即开即用**：内置 GitHub 风明暗双主题，中文用微软雅黑，代码块自动灰底，支持 Anki 夜间模式
- **重跑不重复**：guid 由「牌组名 + 卡号」固定生成，内容改完重跑是**更新**原卡，不会长出重复卡片

## 环境要求

| 项 | 要求 |
|---|---|
| Python | 3.8 及以上（实测 3.10 / 3.13） |
| 第三方库 | 仅 **genanki** |
| 操作系统 | 跨平台，Windows / macOS / Linux 均可 |
| Anki | 2.1.x 及以上（导入 `.apkg`） |

`zstandard` 不是必需的，只有当你需要解包分析**别人给的新版 apkg** 时才用得上。

## 安装

```bash
pip install genanki
```

**方式一：作为 Agent Skill 使用**（推荐）

把整个目录放到 skill 目录下，重启会话后即可用自然语言触发：

```bash
# 用户级（所有项目可用）
~/.workbuddy/skills/anki-cards/

# 或项目级（仅当前项目）
<项目>/.workbuddy/skills/anki-cards/
```

触发词：`anki卡片`、`做成 Anki`、`记忆卡片`、`复习卡`、`背诵卡`、`flashcards`。
也可以直接点名：`/anki-cards 把 D:\notes\k8s.md 做成卡片`。

**方式二：只用脚本**

不装 skill 也能用，`build_apkg.py` 是独立的命令行工具：

```bash
python scripts/build_apkg.py --md cards.md --deck "Network::SRv6"
```

## 基本使用流程

### 1. 写卡片稿

按下面的格式写一个 `.md`。脚本靠这个结构解析，格式错了抽不出卡。

```markdown
# SRv6 记忆卡片

## 一、概念

### 01
- **正面**：SRv6 的 SID 由哪三部分组成？
- **背面**：**Locator**（路由可达）+ **Function**（转发行为）+ **Argument**（可选参数）。
- **标签**：srv6::概念

### 02
- **正面**：SRv6 BE 的报文里有 SRH 吗？
- **背面**：**没有**。BE 只靠 IPv6 目的地址逐跳转发，不压 SRH。
- **标签**：srv6::be
```

| 项 | 要求 |
|---|---|
| 卡片标题 | `### ` + 数字，连续、不重复（`01` 或 `1` 都行） |
| 字段 | 每张卡三行：`- **正面**：`、`- **背面**：`、`- **标签**：`，可选 `- **补充**：`（渲染为灰色小字） |
| 每条内容 | **必须写在一行内**，换行后的内容会被丢弃 |
| 标签 | 必须含 `::`，格式 `主题::分组`，建议全小写，不能有空格 |
| 加粗 | `**两个星号**`，渲染为蓝色强调 |

### 2. 先校验，再出包

```bash
# 只校验不生成，适合改完稿先自检
python scripts/build_apkg.py --md cards.md --deck "Network::SRv6" --dry-run

# 校验通过后生成
python scripts/build_apkg.py --md cards.md --deck "Network::SRv6"
```

脚本会检查编号连续性、字段完整性、标签格式、`**` 是否闭合。**不通过直接中止**，不会产出半个坏包。

### 3. 导入 Anki

双击 `.apkg` 即可。牌组用 `::` 表达层级：`All::1 - Network::1 - SRv6` 会在 Anki 里生成三级结构。

## 命令参考

```bash
python scripts/build_apkg.py --md <文件> --deck <牌组名> [选项]
```

| 参数 | 说明 |
|---|---|
| `--md` | 卡片稿路径（**必需**） |
| `--deck` | 牌组全名，`::` 形成层级（**必需**） |
| `--out` | 输出目录，默认与 md 同目录 |
| `--groups` | 分批出包，如 `"1-46:基础,47-96:冲刺"`，按**编号区间**切 |
| `--name` | 文件名前缀，默认取牌组末段的主题名 |
| `--css` | 自定义样式，默认 `assets/card.css` |
| `--model-name` | 卡片类型名称，默认「问答卡」 |
| `--lowercase-tags` | 标签整体转小写 |
| `--tsv` | 额外导出 TSV（默认不产出） |
| `--dry-run` | 只校验，不生成文件 |

分批示例：

```bash
python scripts/build_apkg.py --md cards.md --deck "All::1 - Network::1 - SRv6" \
    --groups "1-46:基础,47-96:冲刺" --out ./decks
```

产出 `SRv6__1 - 基础.apkg`（46 张）和 `SRv6__2 - 冲刺.apkg`（50 张）。

> **分批请按编号区间切，不要按标签字典序切。** 标签顺序和章节顺序经常不一致，按字母序切会把「可靠性 / 演进 / 场景」这类本该归入基础的卡切丢。

## 输出说明

| 模式 | 产物 |
|---|---|
| 单包 | `<主题>.apkg`，一个牌组 |
| 分批 | `<主题>__1 - 基础.apkg`、`<主题>__2 - 冲刺.apkg` … |

所有主题共用同一个 `MODEL_ID`，因此多个包导入后**复用同一个卡片类型**，不会在 Anki 里堆出多个同名模板。

## 适用场景

- 技术知识整理（协议、框架、命令、原理）
- 考证与面试准备（一题一卡，按标签筛出「面试」子集单独刷）
- 语言词汇、术语表
- 从视频字幕、课程讲义、项目文档中提取要点

## 不适用场景

- 需要**图片遮挡**或**填空（Cloze）**的卡片 —— 脚本只生成问答卡，需要自己改 `assets/card.css` 与模板
- 大量公式、图表的卡片 —— Markdown 转 HTML 后公式不会渲染
- 需要保留原文段落的长文本记忆 —— 拆成原子问答反而破坏语境

## 已知限制

1. **只支持问答卡**（Basic）。Cloze、图片卡需自行扩展模板。
2. 字段**必须单行**。解析器每个字段只取第一行，换行后面的内容会静默消失。
3. 编号必须**连续**，不能有空洞；跨文件的重复编号要靠重新整理解决。
4. `--tsv` 导出的文件是 UTF-8 无 BOM + Tab 分隔，**不要用 Excel 打开另存**，编码和制表符都会被破坏。
5. `SKILL.md` 里的 Python 解释器路径是按作者本机环境写的，换机器请改成你自己的 `python` 路径（或在 skill 里直接写 `python`）。

## 目录结构

```
anki-cards/
├── SKILL.md                  # Agent 使用说明（工作流、写作规范、常见坑）
├── README.md
├── assets/
│   └── card.css              # GitHub 风明暗双主题样式
├── references/
│   └── card-writing.md       # 写卡规范：拆卡标准、答案结构、覆盖度自检
└── scripts/
    └── build_apkg.py         # Markdown → apkg / TSV
```

## 与 qa-batch 的关系

`qa-batch` 负责把**一批材料**整理成问答资料，产出的 Markdown 与本项目的卡片稿**字段级一致**，可以直接用本脚本出包：

```
原始材料 → [qa-batch] → 复习资料_主题.md → [anki-cards] → .apkg
```

单独用本 skill 时，卡片稿由人（或 Agent）直接写；接上 `qa-batch` 后，就变成「多来源材料 → 牌组」的流水线。
