# 卡片撰写规范

写卡之前读一遍。这份规范来自实战：同一份 29 分钟的技术视频，按下面的方法拆出 96 张卡，用户复习时没有出现"卡太胖记不住"或"卡之间互相依赖"的问题。

## 一、拆卡的唯一标准：一张卡只考一个知识点

判断方法：问自己"这张卡的答案是**一个**东西，还是**一串**东西？"

- 一个定义、一个判断、一条流程的**某一跳**、一组**并列且同质**的要点 → 一张卡
- 一串跨章节的因果链 → 拆成多张

反面例子：
> 正面：SRv6 的原理、SID 结构和转发流程是什么？
> 背面：（400 字）

这种卡背下来也不会用，因为回忆时无法定位。正确做法是拆成"SRH 承载哪两个关键信息""SID 由哪三段组成""支持 SRv6 的节点做哪三步"三张。

**例外**：面试型大局题允许一张卡覆盖一个完整论述（见第三节），因为它考的就是"能不能一段话讲清"。

## 二、答案的写法

### 长度

- 细节卡：**1～3 行**，或 2～4 个要点
- 大局型卡：**3～5 行**，按固定结构组织

超过 5 行就要考虑拆分。Anki 的复习节奏是"每天几百次点击"，长答案会被直接跳过。

### 结构模板

细节卡：

```
【术语/结论】是什么 → 【关键动作】①②③
```

例：
> **背面**：① **SL 减一**，指针偏移到新的活跃段；② 把该段地址复制到 **IPv6 目的地址**；③ 查表向下游转发。

大局型卡（面试口述）：

```
【一句话结论】。（加粗）
【三条支撑】①…②…③…
【一句取舍】。
```

例（"SRv6 一定比 SR-MPLS 好吗"）：

> 不绝对。**SR-MPLS 开销更小、现网成熟**；**SRv6 胜在纯 IP 化、可编程、跨域与业务链**。选型看两点：目标网是否 IPv6 化，是否需要端到端可编程。

### 加粗的用法

**只加粗关键词，不整句加粗**。加粗在样式里是蓝色，一整行蓝色等于没有重点。

- 好：`报文中**不含 SRH**，只用一个 IPv6 形式的 SID`
- 差：`**报文中不含 SRH，只用一个 IPv6 形式的 SID完成转发**`

### 数字与不确定表述

凡来自厂商材料或非标准来源的数字，写成"**通常 / 可达 / 最多**"，不要写成硬指标。被追问出处时，"通常 50ms 级"比"50ms"安全得多。

已知容易翻车的：压缩率（75%）、保护倒换时间（50ms）、部署规模（350 张网）——这些都是特定条件或特定年份的数据。

## 三、卡片类型与它们的写法差异

| 类型 | 考什么 | 答案特征 | 占比建议 |
|---|---|---|---|
| 细节卡 | 记得住吗 | 短、精确、可判定对错 | 50%～60% |
| 对比卡 | 分得清吗 | 两列对照，每行一个维度 | 10% |
| 大局型（面试） | 讲得清吗 | 结论+三条支撑+取舍 | 20% |
| 选型卡 | 会决策吗 | 判断标准 → 选项 → 取舍 | 10% |
| 架构卡 | 画得出整张图吗 | 分层/分角色，自顶向下 | 10% |

**选型卡和架构卡最容易被忽略**，但它们才是"能不能干活"的分水岭。审阅卡片稿时，先看这两类有没有。

## 四、分组：按认知递进，不按文档章节

文档的章节顺序是"写给人读的"，卡片的顺序应该是"按记忆依赖排的"。参考分组骨架：

1. **概念与背景**——是什么、为什么有它
2. **机制与报文**——内部怎么运转
3. **结构与类型**——拆开看零件
4. **具体形态**——BE / TE 这类并列的实现
5. **对比**——与替代方案的区别
6. **扩展场景**——跨域、多域、组网
7. **演进与运维**——保护、迁移、可视化
8. **大局型面试题**——一段话讲清一件事
9. **技术选型**——该不该上、上哪种
10. **整体架构**——画一张图

每组 5～8 张为宜。少于 3 张说明这组没写透，多于 10 张说明该拆组。

## 五、标签体系

格式统一为 `主题::分组`，两段，全小写（对齐常见的 `k8s::core` 写法）：

```
srv6::概念   srv6::SRH   srv6::BE   srv6::对比   srv6::面试   srv6::架构
```

规则：
- `::` 是 Anki 的层级分隔符，`srv6::架构` 会自动归到 `srv6` 下
- 分组名不超过 6 个字，避免标签面板被撑爆
- 一组标签只对应一个主题，不要把 `srv6::面试` 复用给别的技术

## 六、独立性：卡片之间不能互相指路

每张卡必须能被**单独抽到**时读懂。

- 禁止：`见第 38 张`、`如上所述`、`接上一张`
- 允许：在正文里补一句必要的上下文

如果两张卡确实冲突（比如早期结论与后期演进），**两张都保留，各自写清适用条件**，并在卡片稿的说明区注明关系。这比删掉一张更安全——复习时能看到"认识是怎么演进的"。

## 七、覆盖度自检

交稿前按这七个维度过一遍，缺哪块补哪块：

- [ ] 定义与术语（能不能一句话说清）
- [ ] 机制与流程（内部怎么动）
- [ ] 操作与配置（怎么落地）
- [ ] 对比与选型（和谁比、选哪个）
- [ ] 故障与边界（什么情况不适用）
- [ ] 演进与现状（版本、标准、时间点）
- [ ] 整体架构（能不能画出全图）

**"什么情况不该用"这一类反向卡价值极高**，因为它证明你真的理解了适用边界，而不是背了宣传材料。

## 八、常见坏卡清单

| 坏卡 | 症状 | 改法 |
|---|---|---|
| 胖卡 | 一张卡 5 个要点以上 | 拆 |
| 空卡 | 答案是"是/不是"、"重要"、"有多种" | 补具体内容，或删 |
| 循环卡 | 用术语解释术语 | 换成动作或结果描述 |
| 依赖卡 | 需要看上一条才懂 | 补上下文 |
| 抄书卡 | 整段原文搬运 | 压缩成关键词 + 结构 |
| 假精确卡 | 抄了来源不明的精确数字 | 改成"通常/可达" |
