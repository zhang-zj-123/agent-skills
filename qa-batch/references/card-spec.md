# 写卡规范（批量场景版）

一份材料读完之后，怎么写才不是"抄了一遍"。下面的规则可以直接当自检清单用。

## 一、三类知识，缺一类就是没读透

每份材料都要产出三类，比例参考：

| 类型 | 是什么 | 占比 | 例 |
|---|---|---|---|
| **重点** | 主干概念、机制、流程 | 50–60% | "SR 的状态保存在哪里" |
| **考点** | 可被追问的判据、数字、边界 | 20–30% | "SR-TE 三种建路方式分别适合多大规模" |
| **易混** | 两个东西的分界线 | ≥10% | "SR-BE 和 SR-TE 的分界线在哪" |

易混点少于 10%，通常说明只做了摘抄，没有做对比理解。**易混点最值钱**，因为考试和面试都考边界。

## 二、原子化：一张卡只考一件事

判断法：问自己"回忆这张卡时，脑子里是一个东西，还是一串东西？"

- 一个定义、一个判据、一条流程的**某一跳**、一组**并列同质**要点 → 一张卡
- 跨章节的因果链 → 拆

反例：
> 正面：SR 的定义、SID 类型和转发流程是什么？
> 背面：（300 字）

这种卡背下来也用不上。拆成"用一句话说清 SR""三种 SID 各标识什么""报文逐跳做哪两个动作"三张。

## 三、答案写法

长度：**细节卡 ≤120 字**，面试型 ≤200 字。超过就该拆。

结构：

```
【结论/术语】是什么 → 【关键动作】①②③
```

例：
> ① 用栈顶 SID 查表转发；② 若本节点是该 SID 归属，弹出栈顶，下一个变活跃段。

**加粗只给关键词**，不整句加粗。整行蓝色 = 没有重点。

数字不确定时写"通常/可达/接近"，别写死。被追问出处时"通常 50ms 级"比"50ms"安全。

## 四、五条禁令

| 禁止 | 判据 | 反例 |
|---|---|---|
| 空卡 | 答案是"是/不是/有多种/很重要" | "SR 重要吗？" |
| 循环 | 用术语解释术语 | "SID 就是 Segment Identifier" |
| 依赖 | 单卡抽出来读不懂 | "如上所述""见第 12 张" |
| 抄书 | 整段原文搬运 | 连续 3 句以上与原文一致 |
| 假精确 | 抄了来源不明的精确数字 | "必定 50ms 收敛" |

## 五、标签体系

格式 `主题::分组`，两段，全小写，不含空格：

```
sr::概念  sr::sid  sr::be  sr::te  sr::对比  sr::选型  sr::架构  sr::易混
```

- `::` 是 Anki 的层级分隔符，会自动归到 `sr` 下
- 分组名 ≤6 字，否则标签面板被撑爆
- **标签里不能有空格**：Anki 会把空格当多个标签分隔符

## 六、卡片稿格式（脚本按行解析，错了就抽不出来）

```markdown
## 概念与背景

### 001
- **正面**：问题？
- **背面**：答案，关键词用 **两个星号**。
- **标签**：sr::概念
- **补充**：可选，显示为灰字备注
```

硬约束：

| 项 | 要求 |
|---|---|
| 卡号 | `### ` + 数字，每个文件从 001 起连续、不重复 |
| 字段 | 每张至少 正面 / 背面 / 标签 三行 |
| 单行 | 每条内容必须写在一行内（换行会被静默丢内容） |
| 粗体 | `**` 必须成对 |
| 分组 | 每张卡上方用 `## 分组名` 标一次，后面同组卡片不用重复写 |

## 七、交稿前自检

- [ ] 三类都有（重点 / 考点 / 易混）
- [ ] 每节至少 2 张，每个来源至少 3 张
- [ ] 没有两张卡在问同一件事（同义改写也算）
- [ ] 随机抽 3 张，遮住答案能答出来
- [ ] 每张卡单独看能读懂，不需要前后文
